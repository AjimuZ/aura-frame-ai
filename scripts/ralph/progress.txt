# Ralph Progress Log

## Codebase Patterns

- Keep check scripts equivalent to the commands the runner invokes, so a green script implies green runner checks.
- Under Git Bash, use MSYS_NO_PATHCONV=1 with pwd -W when passing host paths to docker -v.
- When renaming a field that crosses layers, grep every spelling (snake_case, camelCase, DB column, config key, local variable) before declaring the rename complete.
- Copy acceptance criteria character for character into review criteria, since the runner compares exact text.
- Verify a pre-existing working-tree change with the project checks and searches before reporting it done.
- Keep banned terms base64-encoded in guard tests and match by whole identifier tokens (split on non-alphanumerics, underscores and camelCase boundaries) to avoid substring false positives.
- When a rename touches an npm script name, describe it as 'the store test command is now X' instead of quoting the old name in the changelog.
- Keep test files at their existing path when renaming their subject; change content only, because the runner refuses deleted or renamed test files.
- Read personal identifiers such as the Git user name at test time and never store them in a file.
- Build test inputs for guard tests at run time, such as a Windows path from separator pieces, so the guard file does not trigger its own patterns.
- When removing a runtime path, replace it with an explicit, single-source error message constant so callers fail clearly instead of silently or by crashing.
- After deleting a file or script, grep the docs for it and correct any statement that still calls it 'in use'.
- Record checks that could not be run, such as upstream release notes without web access, as explicit gap rows in docs/testing.md.
- Apply cross-cutting security checks (token, Host) as app-level middleware so unknown paths and OPTIONS are guarded too, not just declared routes.
- Compare secrets with hmac.compare_digest, read them from the environment, and fail closed (refuse to start) when they are missing or too short.
- Assert on the absence of access-control-* headers across success, refusal and OPTIONS responses in the same test.
- Take paths from stored records, never from requests. Validate IDs with a strict pattern, and resolve every stored path against its allowed root with is_relative_to before serving it.
- Delete generated data by an explicit allowlist of subdirectories under a per-library root, unlink symlinks without following them, and refuse configurations where the writable root and the read-only photos root overlap.
- Do not skip a test for an environment gap. Run it where the capability exists, or let it fail visibly.
- Before writing 'not run' in the changelog or roadmap, try the project check script. When the result is known, record the exact count and command in those documents.
- When a later subtask delivers what an earlier progress note called 'still to do', rewrite the earlier sentence in the same change.
- To prove a negative in a container check, pair it with a positive control: the same probe must succeed against a reachable target, and a write refusal must carry the specific error (EROFS), so a missing tool or a permission error cannot pass as isolation.
- Check Compose hardening against `docker compose config --format json` rather than the YAML text, and unit test the checker with one weakened configuration per rule.
- Start a root-context .dockerignore with `*` and re-allow only what the image needs, so personal folders never reach the Docker daemon.
- Test shell scripts by copying them to a temp dir and putting stub executables first on PATH. Stubs log argv and the environment to files, so a test can prove a secret never appears in an argument.
- Pass secrets to child processes through exported environment variables, and give curl its header through a config on stdin (`-K -`), so nothing sensitive appears in the process list.
- Give Electron main modules that touch the OS (spawn, token generation) injectable dependencies, so Node tests can load the compiled dist-electron CJS and assert exact argv and options with a fake.
- Pass secrets and user-chosen paths to child processes only through the env option, never argv, with shell: false. Test the absence of both from argv, events and return values.
- Put a gate on the object that supplies a credential, and check it in the one function that attaches that credential, so the credential cannot be wired without its gate.
- When a teardown can overlap a long-running start, have the teardown await the in-flight start, and record that a stop was requested so the late success cannot mark the service as up.
- For an async Electron quit, always call preventDefault in before-quit, guard against repeats, bound the work, and leave with app.exit, which emits no further quit event.
- When a test's fake cannot prove a wire contract, also compare the client with the real server's routes and models, and report that as read, not run.
- Any new request from Electron main to the API goes through `ApiClient.open`, so it cannot bypass the session gate or attach the token on its own.
- Handlers that answer the renderer take their backend by injection (`MediaProxyBackend`), so a Node test can run them with a fake server and no Electron.
- When leaving work open in a progress note, name the roadmap task that owns each leftover, so the parent item's unchecked state can be explained.
- An IPC handler that must not leak paths or tokens catches every lower-level error and rethrows a fixed message, including `fs.copyFile` errors, which name both paths.
- To prove 'sends nothing', count calls at the injected client as well as requests at the fake server, so the test tells the handler's own gate from the client's.
- A handler that depends on remote state before a local irreversible change (registry removal) calls the remote step first and lets a failure leave the local state untouched.
- When an async step (such as a probe) is added before a spawn, update the fakes in every test that counts spawns, and have them wait for the spawn instead of assuming it is synchronous.
- A host folder given to a container goes through one validation function in main and reaches compose only through the child environment, never through argv; the test asserts both the environment value and its absence from the arguments.
- When a module cannot import the error type because of an import cycle, let it raise the standard OSError and map it to a structured error in the route layer.
- Pin container images by reading `docker inspect --format '{{index .RepoDigests 0}}' <tag>` after a pull. Never guess a digest. Record the date and the source tag next to the pin.
- When a long real run is cut by a tool time limit, rerun a lighter variant that still exercises the path under test (for example `--cpu`), so the exit code is observed. Record both runs honestly.
- Secrets handed to a child process travel only through the environment. The receiving process validates the exact format (here 64 lowercase hex characters) and deletes the variable from its own environment at startup.
- A shell script that must clean up on exit runs its long-lived child with `&` plus `wait`, and sets INT/TERM/HUP traps and an EXIT trap that all call one idempotent cleanup guarded by a flag.
- Treat only 401 and 403 as 'credential refused' and close the request gate on them. Other error statuses must not change session state.
- Test Electron trust boundaries without a new dependency or an Electron binary: inject a fake 'electron' into require.cache, require the compiled main.js, and capture the BrowserWindow options and the will-navigate and window-open handlers from a fake BrowserWindow.
- Compare navigation targets by parsed URL (origin, or protocol plus empty host plus exact path), never with startsWith on the raw string. A prefix check lets look-alike hosts such as localhost:4200.example.com through.
- Shell checks that need writes or network calls belong in a reviewed script under tests/integration/, run through a scripts/check.sh flag, so a session can run them through the allowed entry point.
- Providers return failures as typed results (ok=False plus a short error code) and never raise; a guard wrapper trips to a degraded state and a fallback function supplies a local verdict.
- Clamp every configurable timeout, retry and limit to a documented hard bound when settings are built, and test the clamping.
- Test HTTP clients against a local fake server on 127.0.0.1 and verify image bytes by re-reading them, never by trusting the code path.
- Accept a downloaded artifact only by writing it to a hidden partial file, verifying size, hash and header, then renaming it atomically; delete the partial file in a finally block.
- A service that needs an internet route goes behind its own Compose profile and is started only via `compose run --rm` from one explicit start.sh flag; the compose policy names it as the sole egress service.
- Use an extension allow-list (`.gguf`, `.safetensors`) rather than a block-list for model files, and confirm the format from the first bytes as well.
- Derive an identifier from content (SHA-256), never from a path, so results survive moves and renames; keep pattern validators in the API and in Electron main in step.
- Decode an original once, bake in orientation at that point, and hand every later stage a derived copy with no orientation tag; a stage that cannot find the copy reports it rather than reopening the original.
- Write derived files to `<name>.part` and `os.replace` them into place, so a crash never leaves a truncated file that a later run would accept.
- Test a privacy property from the data side: build a synthetic input that carries the forbidden field (GPS), assert the fixture really has it, then assert it is absent from the record, the database rows, the mirror file and the derived images.
- When an ID scheme merges identical inputs, record every dropped input as its own rejected record with a distinct ID and a stated reason, so a rejection is visible and counted instead of silent.
- Decide format support from decoded content (`image.format`), not the file extension, and keep 'recognized but unsupported' distinct from 'unreadable'.
- Reject policy belongs in one place (the gate). Measurement stages only measure, and anything subjective is a soft flag.

**How it meets the criteria:**
- **The service:** `fetch-models` is defined in compose.yaml and built from `docker/fetch-models/Dockerfile`. It is a one-shot service on the new `egress` network only, behind the profile `fetch`, so no `up` starts it. Its only mount is the writable `models` volume. It runs as uid 10001 with a read-only root filesystem, all capabilities dropped and no-new-privileges. It uses only the Python standard library on the digest-pinned base image.
- **The manifest:** `engine/src/model_fetch/manifest.json` pins all four models (the default and the three bake-off candidates), seven distinct files in total. Each file has its repository, commit revision, file name, size and SHA-256, copied exactly from the task notes. A test checks it against a separate copy of those values. The two upstream files both named `mmproj-BF16.gguf` get separate names in the volume.
- **The checks:** a download goes to a hidden `.partial` file. It is renamed into place only after the size, the SHA-256 and the file header all match; otherwise it is deleted. Only https is used, and redirects must stay on https. Only `.gguf` and `.safetensors` are accepted. Pickle-based formats are refused by name, and a pickle renamed to `.gguf` is refused by its content.
- **The only path:** `./start.sh --fetch-models [model|all]` runs `docker compose --profile fetch run --rm --build fetch-models`. A test proves that no other start.sh path touches the service. `scripts/compose-policy.cjs` refuses any other service on a routed network apart from `gateway` on `frontend`.

## 2026-11-02T13:37:51Z - P04.1
- P04.1 is implemented. Ingest hashes each original with SHA-256 and uses that hash as the photo ID. It decodes the original once, applies the EXIF orientation once, and writes an upright working copy (long side at most 1,536 px, never upscaled) and a 512 px thumbnail. Quality, faces and embeddings now read only the working copy. A moved or renamed file with the same bytes keeps its stored results and is not decoded again. Only capture time, camera make and model are kept from EXIF. Originals are only opened with mode "rb". `bash scripts/check.sh --engine` passed 282 of 282, and `bash scripts/check.sh --node` passed (lint, both builds, 181 of 182 node tests, 1 skipped). I did not run `bash scripts/check.sh --integration` or a full `analyze` run.
- Files changed: engine/src/ingest.py, engine/src/utils.py, engine/src/index_photos.py, engine/src/quality_score.py, engine/src/face_quality.py, engine/src/embeddings.py, engine/src/db.py, engine/main.py, engine/config.yaml, engine/api/storage.py, apps/desktop/electron/media-proxy.ts, tests/integration/backend-run.sh, tests/media-proxy.test.cjs, engine/tests/test_ingest.py, engine/tests/conftest.py, engine/tests/test_engine.py, engine/tests/test_pipeline.py, engine/tests/test_api_routes.py, CHANGELOG.md, docs/roadmap.md, docs/assessment.md, docs/pipeline.md, docs/architecture.md, docs/testing.md
- **Learnings for future iterations:**
  - The photo ID is the full SHA-256 as 64 lower-case hex digits: `photo_id_for(path)` equals `file_sha256(path)`. PHOTO_ID_PATTERN (engine/api/storage.py) and the Electron media proxy accept both the new shape and the older `IMG_` plus 10 upper-case hex shape. The older shape can be dropped once nothing stored uses it.
  - Derived files live in `working_dir/copies/<id>.jpg` and `thumbs_dir/<id>.jpg`. Use `working_copy_path`, `thumbnail_path_for` and `read_working_bgr` from engine/src/utils.py; `read_working_bgr` returns None when the copy is missing, and there is deliberately no fallback to the original.
  - `ingest_image(..., known={id: Photo})` and `index_photos(..., known=...)` skip the decode when the stored record and its derived files exist, and set the transient `Photo.carried_over`. engine/main.py `cmd_analyze` passes only photos whose `rank` stage is done, and treats `carried_over` as resumed.
  - Policy for byte-identical files: they share one ID, so `index_photos` keeps the first in path order and drops the rest. `mark_duplicates` level 1 is therefore no longer reached from `index_photos`; it still works on records that carry the same `file_hash`.
  - `db.upsert_photo` now deletes other records with the same `file_path` and a different ID, with their scores, faces, embeddings and jobs. This replaces stale records for edited files and for records from the older ID scheme.
  - Classic quality measures (blur, brightness, contrast) now run on the working copy, which has a long side of at most 1,536 px. The thresholds in config.yaml were tuned on full-size images and may need retuning in P04.2.
  - The new stages must read the working copy: P04.3 (Q-ReAlign scoring and SigLIP 2 embeddings) should use `working_copy_path`, not `photo.file_path`. The legacy `src/cloud` preparer still opens originals and is removed in P05.5.
  - Tests that call `score_quality` or `score_faces` must ingest first and use the `data_config` fixture from conftest.py, which redirects generated files under tmp_path. A `Photo` built by hand has no working copy.
  - To count decodes in tests, wrap `PIL.Image.open` and `cv2.imread` with `monkeypatch` and record the path (see `DecodeRecorder` in engine/tests/test_ingest.py). To build EXIF with GPS, hand-encode the TIFF block (`_rich_exif`); Pillow's nested `get_ifd` writes did not produce a GPS block when I tried it.

## 2026-11-02T13:50:51Z - P04.2
- P04.2 is implemented. The gate rejects only four things: an unreadable file (`failed_read`), an unsupported format, a byte-identical copy, and a long side under 256 px. Brightness and blur no longer reject. A screenshot only gets the `local_flag_screenshot` flag. The legacy `strict` gate mode and its settings are removed.

- **Unsupported format:** ingest now checks the decoded content against JPEG, MPO, PNG, WebP and HEIF, so a GIF saved as `.jpg` is rejected as `unsupported_format`. Truly corrupt bytes stay `unreadable_image`.
- **Byte-identical copies:** `index_photos` used to drop later copies silently. Each copy now becomes its own rejected record (`duplicate-<path hash>` ID, shared `file_hash`, reason `duplicate_exact`, no working copy), so the rejection is visible and counted.
- **Size rule:** `too_small` when the long side is under `local_gate.min_long_side` (256).

**Checks:** `bash scripts/check.sh --engine` passed 287 of 287 (the 282 earlier plus 5 new gate tests). I did not run the node checks, the integration check, or a full `analyze` run; no node, compose or integration file changed.

**Not done:**
- Documents get no flag yet; that arrives with P04.4.
- Only files with a supported extension are discovered, so a `.gif` or `.bmp` file is never listed.
- `engine/src/export_results.py` still maps reject reasons that nothing emits any more (`too_blurry`, `too_dark`, `no_face` and others). I left them alone.
- A photo with a brightness mean or Laplacian variance of exactly 0 gets no `low_light` or `possible_blur` flag, because the existing flag code treats 0 as unmeasured.

Privacy and security: no new network or filesystem access. Originals are still only read.
- Files changed: engine/src/local_gate.py, engine/src/ingest.py, engine/src/index_photos.py, engine/main.py, engine/config.yaml, engine/tests/test_sanity_gate.py, engine/tests/test_openai_quality.py, engine/tests/test_engine.py, engine/tests/test_ingest.py, CHANGELOG.md, docs/pipeline.md, docs/assessment.md
- **Learnings for future iterations:**
  - The gate reject reasons are `exact_duplicate`, `unsupported_format` and `too_small` (`hard_reject`), plus `failed_read` for unreadable files. `local_gate.min_long_side` (256) is the only reject setting left in config.
  - `mark_duplicates` no longer takes `keep_near_duplicates`; near-duplicates are always flagged and kept. The `local_gate.mode`, `hard_reject` and extreme-threshold keys are removed from engine/config.yaml.
  - Byte-identical copies are now separate records: `ingest.duplicate_record(path, original)` gives ID `duplicate-<32 hex of the path hash>`, the shared `file_hash`, status rejected and reason `duplicate_exact`, and no working copy or thumbnail. They are not `carried_over`, so `cmd_analyze` puts them in `fresh` and the gate records them each run. The ID does not match `PHOTO_ID_PATTERN`, like `unreadable-` IDs; nothing serves images for them.
  - `ingest.SUPPORTED_FORMATS` is the allow-list of Pillow format names (JPEG, MPO, PNG, WEBP, HEIF). A format outside it returns early as `unsupported_format` before `image.load()` and before any derived file is written. Garbage bytes that Pillow cannot identify still raise and become `unreadable_image`.
  - `discover_images` still filters by extension, so a supported-extension file with other content is rejected but a `.gif` or `.bmp` file is never seen.
  - Screenshots are only flagged (`local_flag_screenshot`). The documents flag must come from the P04.4 content tag, as a soft flag with no reject rule.
  - The flag code treats a brightness mean or Laplacian variance of exactly 0 as unmeasured, so an all-black or perfectly flat image gets no low_light or possible_blur flag. Tests avoid asserting those flags at 0.
  - P04.8 deletes `local_gate.py`; the tests in `test_sanity_gate.py` check the policy through `index_photos`, `score_quality` and `run_local_gate`, so they are the ones to port. `export_results._REJECT_FOLDERS` still has dead reasons (`too_blurry`, `too_dark`, `no_face`, `likely_screenshot` and others) that can be removed with it.
  - To keep a synthetic screenshot flat after the JPEG working copy, align colour blocks to 8 px boundaries; otherwise ringing raises the unique-gray-level ratio above the 0.35 screenshot heuristic.
