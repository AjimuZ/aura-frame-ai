## Codebase Patterns

- Keep check scripts equivalent to the commands the runner invokes, so a green script implies green runner checks.
- Under Git Bash, use MSYS_NO_PATHCONV=1 with pwd -W when passing host paths to docker -v.
- When renaming a field that crosses layers, grep every spelling (snake_case, camelCase, DB column, config key, local variable) before declaring the rename complete.
- Copy acceptance criteria character for character into review criteria, since the runner compares exact text.
- Verify a pre-existing working-tree change with the project checks and searches before reporting it done.
- Keep banned terms base64-encoded in guard tests and match by whole identifier tokens (split on non-alphanumerics, underscores and camelCase boundaries) to avoid substring false positives.
- When a rename touches an npm script name, describe it as 'the store test command is now X' instead of quoting the old name in the changelog.
- Keep test files at their existing path when renaming their subject; change content only, because the runner refuses deleted or renamed test files.
- Read personal identifiers such as the Git user name at test time and never store them in a file.
- Build test inputs for guard tests at run time, such as a Windows path from separator pieces, so the guard file does not trigger its own patterns.
- When removing a runtime path, replace it with an explicit, single-source error message constant so callers fail clearly instead of silently or by crashing.
- After deleting a file or script, grep the docs for it and correct any statement that still calls it 'in use'.
- Record checks that could not be run, such as upstream release notes without web access, as explicit gap rows in docs/testing.md.
- Apply cross-cutting security checks (token, Host) as app-level middleware so unknown paths and OPTIONS are guarded too, not just declared routes.
- Compare secrets with hmac.compare_digest, read them from the environment, and fail closed (refuse to start) when they are missing or too short.
- Assert on the absence of access-control-* headers across success, refusal and OPTIONS responses in the same test.
- Take paths from stored records, never from requests. Validate IDs with a strict pattern, and resolve every stored path against its allowed root with is_relative_to before serving it.
- Delete generated data by an explicit allowlist of subdirectories under a per-library root, unlink symlinks without following them, and refuse configurations where the writable root and the read-only photos root overlap.
- Do not skip a test for an environment gap. Run it where the capability exists, or let it fail visibly.
- Before writing 'not run' in the changelog or roadmap, try the project check script. When the result is known, record the exact count and command in those documents.
- When a later subtask delivers what an earlier progress note called 'still to do', rewrite the earlier sentence in the same change.
- To prove a negative in a container check, pair it with a positive control: the same probe must succeed against a reachable target, and a write refusal must carry the specific error (EROFS), so a missing tool or a permission error cannot pass as isolation.
- Check Compose hardening against `docker compose config --format json` rather than the YAML text, and unit test the checker with one weakened configuration per rule.
- Start a root-context .dockerignore with `*` and re-allow only what the image needs, so personal folders never reach the Docker daemon.

- **Providers:** `GET /providers` reports configuration only: local scoring `available`, local vision model `not_configured`, Codex `disabled`. It contacts nothing and does not mention Ollama.
- **Data:** `DELETE /libraries/{id}/data` removes only `working`, `output` and `reports` under that library's directory in the data root. It is idempotent and unlinks symlinks without following them. It never touches the photos root, and the two roots may not contain each other.
- **Review:** `GET` and `PUT /libraries/{id}/review` use the `slotAssignments`, `locks` and `shortlist` shape of the bridge.
  - `PUT` validates a Pydantic model that rejects unknown fields and bounds key and list sizes. Invalid bodies get 422.
  - `GET` returns null before the first save.

Library ids must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`. The request guard from P02.3.1 covers all of these routes, and the tests check 401 without the token and 403 for a foreign Host on each.
